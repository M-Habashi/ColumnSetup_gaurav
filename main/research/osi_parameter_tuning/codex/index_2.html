Online Stability Indicator Tuning Guide

The Online Stability Indicator, abbreviated as OSI, is the part of the hybrid-simulation controller that watches whether the actuator and specimen loop is getting close to instability. The current design is called Fable in the repository. It reads command displacement and measured displacement, estimates a stability margin, and then adjusts one scalar authority factor that multiplies the command sent to the MTS.

This guide defines every signal before using it, explains why each branch is needed, gives the equations used by the implementation, and ends with the parameters most useful for tuning OSI behavior.

System Story

The real-time hybrid simulation sends a displacement command to the actuator. The actuator, controller, and physical specimen return a measured displacement. If the specimen degrades or the actuator loop changes, the same command can produce a more dangerous measured response. OSI detects that change online.

1. CommandThe numerical substructure produces command displacement.
2. PlantThe command passes through the controller, actuator, and specimen.
3. MeasurementThe actuator displacement is measured and logged.
4. OSIFable estimates a stability margin from recent command and measurement windows.
5. AuthorityThe authority factor scales the command path when margin is low.
Why one authority factor? The PID gains and phase-lead parameters are not monotone safety knobs: changing one can improve one condition and hurt another. The authority factor is intended to be simpler for online protection. Lower authority means the controller command sent to the plant is reduced, so the loop is pulled away from the risky operating point.

Why Three OSI Branches Are Needed

BranchWhat it watchesWhy it existsMain output
Slow ST branch Command-driven frequency bins where dd and dm are coherent. When the command excites a frequency, this branch can estimate the closed-loop transfer and compute the best margin estimate. b_st
Residual branch Output power in hazard frequencies that are quiet in the command. Instability can grow in a frequency band that the command is not directly exciting. This branch catches that by watching unexplained measured motion. b_res
Fast quick-dip branch Short-memory transfer changes and quiet-band bursts. The slow branch is accurate but delayed. The fast branch exists to shed authority quickly during sudden changes. b_fast and trip_reason

The selected margin b_osi is normally the lower of the slow coherent branch and the residual branch. During a fast transfer collapse, the runtime can also expose the fast dip so the authority law responds immediately.

Equations With Definitions

First define the spectra. The command signal is dd, the measured signal is dm, and a Hann-windowed Fast Fourier Transform is taken over recent samples. The implementation stores: Suu for command autospectrum, Syy for measured autospectrum, and Suy for cross spectrum from command to measurement.

M = Suy / Suu
Here M is the estimated closed-loop transfer from command displacement to measured displacement.

The coherence value tells whether a frequency bin is actually explained by the command. Fable uses it to decide whether a bin belongs to the slow coherent branch or the residual quiet branch.

g2raw = abs(Suy)^2 / max(Suu*Syy, tiny^2)
gamma2 = max(0, (k_eff*g2raw - 1)/(k_eff - 1))

The stability margin is computed from the sensitivity-like term S = 1 - M and the transfer-like term T = M. A smaller margin means the loop is closer to instability.

b(w) = 1 / (sqrt(2)*sqrt(abs(1 - M)^2 + abs(M)^2))
b_st = min over accepted coherent bins of b(w)

The residual branch removes the part of output power explained by the command. It compares the remaining power with a calibrated healthy baseline. If unexplained power grows, the residual margin is reduced.

res = Syy * max(1 - gamma2, residual_floor)
ratio = res / baseline
z = (log(ratio normalized by quiet-bin median) - mu0) / sigma0
b_res = anchor / sqrt(growth)

The authority law lowers auth when the selected margin is below target. The main drop shape is multiplicative: a lower margin produces a deeper authority target.

a_pl = a_cont * (max(b_size, 0.02)/target)^down_power
auth moves toward a_pl at no more than down_rate per second

Speedgoat Implementation Notes

The Speedgoat runtime is control_and_HS/OSI/fable_osi_runtime.m. It is called once per 2048 Hz base-rate sample. It does not compute the whole OSI update in one tick. Instead it spreads the work across bounded phases and publishes outputs after 56 ticks, about 27 ms.

Runtime itemMeaningWhen to tune it
fable_pred_enableTurns the authority prediction grid on or off.First thing to disable if timing is tight.
step_sFast path and authority update cadence.Increase from 0.125 to 0.25 if CPU load is too high.
hop_sSlow branch update cadence.Increase from 0.25 to 0.5 if slow-pipeline load is too high.
band_hzFrequency range kept in the OSI grids.Narrow it if unused high-frequency bins cost too much.
