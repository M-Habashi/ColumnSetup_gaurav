vHS Phase-Lead Optimizer v2 — User Guide

Finds the phase-lead prefilter GT(s) on the numerical dd command that minimizes J4 while holding the num·GT·PID·Hdc,dm·exp NCF margin at or above your target. Same inputs and same saved-file format as before — new engine underneath.

1. Quick start

Exactly like the old workflow:

% optional: set the NCF target (default 0.45)
ncfmargin = 0.40;

% then run the wrapper (same file pickers for specimen / exp_tf / FEM)
run('control_and_HS\d_HS\optimize_vHS_phase_lead_min_ncf.m')

You will be asked to pick the specimen, exp_tf and FEM files the same way as before (unless you set the override variables below). The optimizer then runs four stages, prints live progress, saves the result under saved_results\phase_lead\ and opens two figures.

The goal it optimizes: minimize J4 (first-floor response error vs the reference FEM) subject to NumPhaseLeadExpNCFMargin ≥ ncfmargin as a hard constraint. The constraint is almost always active at the optimum — the final NCF typically lands exactly on your target.

2. Workspace overrides (same interface as before)

Set any of these variables before running the wrapper; all are optional.

VariableMeaning
ncfmargin / ncf_margin Target NCF margin (default 0.45).
specimen_file_override / exp_specimen_file_override Full path to a saved_results\specimens MAT file (skips the picker).
h_dc_dm_model_file_override Full path to a saved_results\exp_tf file containing H_dc_dm.
fem_file_override Full path to a saved_results\fem file.
pid_gain_override [P I D N] vector or struct (default [0.15 20 0.0015 512]).
phase_lead_file_name_override Output MAT name under saved_results\phase_lead (default pl_7000_ncf4).
phase_lead_optimizer_config Struct of engine options merged on top of the defaults (see below).

3. Engine options

Everything lives in one config struct. The full list with defaults is in defaultConfigV2() inside utils_HS\optimize_vHS_phase_lead_v2.m; the ones you will actually touch:

OptionDefaultWhat it does
target_ncf_margin0.45 The hard NCF constraint (also settable via ncfmargin).
phase_lead_section_count1 Number of cascaded lead sections. 1 keeps the classic (zero, pole) pair; 2 gives a 2z/2p filter.
center_frequency_bounds_hz[0.5 80] Search box for the section center frequency √(z·p).
ratio_bounds[1.01 25] Search box for the total pole/zero ratio (more ratio = more lead).
optimization_record_fraction1.0 Fraction of the earthquake record used during the search (the fast simulator makes the full record affordable).
map_center_count × map_ratio_count96 × 72 Resolution of the analytic NCF feasibility map (stage 1, no simulations — takes ~2 s).
explore_budget / boundary_budget 90 / 45 Number of simulated candidates inside the feasible region and on the NCF boundary (stage 2).
zoom_seed_count, zoom_iterations, zoom_grid_size3, 5, 5 Adaptive local zoom refinement (stage 3).
use_fmincon_polish, polish_max_evaluationstrue, 150 Final SQP polish with the NCF target as a nonlinear constraint (stage 4).
save_results, plot_results true, trueSave the phase-lead MAT / show figures.
save_best_checkpoint, best_checkpoint_file true, auto Periodically saves the best-so-far to vHS_phase_lead_v2_best_checkpoint.mat so a long run can be interrupted safely.

Example — 2-section lead with a tighter frequency box:

phase_lead_optimizer_config = struct( ...
    'phase_lead_section_count', 2, ...
    'center_frequency_bounds_hz', [1 40], ...
    'ratio_bounds', [1.05 16]);
ncfmargin = 0.40;
run('control_and_HS\d_HS\optimize_vHS_phase_lead_min_ncf.m')

4. Adding goals to the objective

The score minimized among feasible candidates is

objective = J4_raw + sum(extra penalties) + custom term

Two extension hooks, both configured without touching the engine:

4.1 Penalize any metric: extra_penalties

% each entry: weight * max(0, metric - threshold)^power
phase_lead_optimizer_config.extra_penalties = [ ...
    struct('metric', 'max_dc_dm_ratio',      'weight', 2.0, ...
           'threshold', 1.5, 'power', 2), ...   % keep dc/dm below ~1.5
    struct('metric', 'peak_command_ratio',   'weight', 0.5, ...
           'threshold', 1.2, 'power', 1)];      % limit command growth

Any field of the metrics struct can be named: j4_raw_percent, tracking_nrmse_percent, lead_change_percent, peak_command_ratio, max_dc_dm_ratio, max_dd_lead_dc_ratio, stability_margin, num_phase_lead_exp_gm_db, num_phase_lead_exp_pm_deg, num_phase_lead_exp_ncf_margin, max_abs_pole, … The legacy knobs max_dc_dm_penalty_weight and max_dd_lead_dc_penalty_weight still work and are converted to penalty entries automatically.

4.2 Arbitrary terms: custom_objective_fcn

% full access to metrics, simulated signals and the candidate filter
phase_lead_optimizer_config.custom_objective_fcn = ...
    @(metrics, signals, phase_lead) ...
        0.1*phase_lead.max_phase_lead_deg ...      % prefer gentle leads
      + 5*max(0, max(abs(signals.dc_sample)) - 40); % cap dc at 40 mm
Keep custom terms in the same order of magnitude as J4 (tens of percent) so they trade off sensibly, and keep them smooth if you can — the final polish differentiates the objective.

  • * new best lines fire on every improvement (parameters included, so you can stop anytime and use them).
  • Progress lines show evaluated/planned, elapsed time and ETA roughly every 2 s (progress_interval_seconds).
  • The run ends with a full-record summary, the top-10 candidate table, a copy-pastable phase_lead = struct(...) literal, the J1–J7 validation table and the stability table.

5.2 Saved file (vHS-compatible)

The result MAT keeps the legacy format (phase_lead_tf, phase_lead, metrics, config, result tables, …), so vHS.m loads it with no changes. A best-so-far checkpoint is also saved during the run.

5.3 Figures

NCF feasibility map — the search space at a glance: color is the NCF margin, the black contour is your target, dots are the simulated candidates (green = feasible), the star is the returned optimum. If the star does not sit on the black contour, the constraint was not active and more lead did not help.

Control check — the classic time-domain overlay (d_n, lead-shaped d_n, d_r, dc, dm and the measured force) for the selected candidate on the full record.

6. Behavior worth knowing

  • Unreachable targets are detected, not chased. If no point in the search box reaches the target NCF, stage 1 says so immediately (with the maximum achievable value) and the search returns the candidate that gets closest with the lowest J4. Example: with the sp1_7000 setup, target 0.45 is impossible for one section — the map proves it in ~2 s (max 0.4167).
  • Deterministic. No random restarts: the same inputs reproduce the same answer.
  • Repeated candidates are cached, so the polish stage can finite-difference freely without re-simulating.
  • J4 rounding. The official J4 metric rounds to 0.01 %. The optimizer internally minimizes the unrounded value (j4_raw_percent) and reports both.
Watch the safety metrics. The optimizer only enforces the NCF and stability constraints. If the best candidate shows a large MaxDCDMRatio or an aggressive MaxPhaseLead_deg, add a penalty (Section 4) rather than hand-picking a milder candidate from the table.

7. Calling the engine directly (scripting)

addpath('control_and_HS\d_HS\utils_HS');
cfg = struct( ...
    'specimen_file',      'saved_results\specimens\sp1_7000.mat', ...
    'h_dc_dm_model_file', 'saved_results\exp_tf\tf_sp1_7000_20260627_210411.mat', ...
    'fem_file',           'saved_results\fem\fem_sp1_7000.mat', ...
    'target_ncf_margin',  0.40, ...
    'phase_lead_file_name', 'pl_7000_ncf40_v2.mat');
result = optimize_vHS_phase_lead_v2(cfg);
result.best_phase_lead          % the winning filter
result.best_metrics             % full-record metrics
result.optimization_result_table% every simulated candidate, ranked
result.map                      % the NCF feasibility map (centers, ratios, ncf)

For tests and tooling, optimize_vHS_phase_lead_v2('helpers') returns handles to the internal building blocks (problem preparation, the fast evaluator, the analytic NCF).

See the algorithm document for how the engine works and measured comparisons against the legacy optimizer.
